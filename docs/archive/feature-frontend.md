# План разработки: веб-интерфейс

> **Статус:** все ветки готовы. Запуск через Docker Compose описан в [`docker.md`](../docker.md).
>
> Этот файл собирает требования к интерфейсу из [`TASK.md`](../TASK.md) и [`TODO.md`](../TODO.md) и удалённого
> тестового интерфейса (`git show 00f1e93^:backend/src/edm_auditor/api/web.py`). Описание API находится в
> [`backend/README.md`](../../backend/README.md).

## 1. Цель и границы

Пользователь должен пройти весь сценарий в браузере: загрузить НПА, проверить правила, загрузить документ,
настроить и запустить аудит, разобрать нарушения на экране с подсветкой.

**Входит:** FR-1.1 (загрузка), FR-4.1–4.3 (экран аудита), FR-5.1–5.2 (НПА и правила), настройка аудита,
типы документов, диагностика НПА.

**Не входит:**

- экспорт отчёта (FR-4.4): отдельная ветка после интерфейса, в курсовом только HTML;
- вход, пользователи и роли: это диплом, см. [`DIPLOMA.md`](../DIPLOMA.md), но интерфейс к ним готовится (раздел 4);
- большие НПА вроде Трудового кодекса: работаем только с маленькими файлами.

## 3. Технические решения

| Область          | Решение                                 | Почему                                                          |
|------------------|-----------------------------------------|-----------------------------------------------------------------|
| Расположение     | `frontend/` в корне репозитория         | Рядом с `backend/`                                              |
| Основа           | React, TypeScript, Vite, Tailwind CSS   | Задано в `TASK.md`                                              |
| Компоненты       | shadcn/ui и значки Lucide               | Задано в `TASK.md`; код компонентов лежит в проекте             |
| Маршруты         | React Router                            | Экраны получают свои адреса, а маршруты можно защищать правами  |
| Данные API       | TanStack Query                          | Кэш, состояния загрузки и повтор; кэш легко очистить при выходе |
| Типы API         | `openapi-typescript` из `/openapi.json` | Типы не расходятся с бэкендом                                   |
| Запросы          | Прокси Vite на `/api`                   | CORS не нужен, а `X-Total-Count` виден без настройки            |
| Тесты            | Vitest и Testing Library                | Те же инструменты, что и у Vite; сеть и ключи не нужны          |
| Устройства       | Только компьютер, ширина от 1280 px     | Две панели экрана аудита не помещаются на телефоне              |
| Тема             | Только светлая, цвета через переменные  | Другие темы появятся в дипломе, см. раздел 4а                   |
| Язык             | Только русский, тексты в словаре        | Другие языки появятся в дипломе, см. раздел 4а                  |
| Запуск на защите | Docker Compose, ветка 5                 | Одна команда вместо двух процессов                              |

Поля отчёта `summary` и `selection` в OpenAPI описаны как произвольный объект, поэтому их типы пишутся
вручную, и в них нужно проверять, что поле есть.

Прокси Vite работает только при разработке. В Docker Compose интерфейс и API тоже должны отвечать с одного
адреса, чтобы не понадобился CORS: путь `/api` в клиенте не меняется. Поэтому собранный интерфейс раздаёт
nginx, и он же передаёт `/api` бэкенду, см. [`docker.md`](../docker.md).

## 4. Подготовка к авторизации и ролям

Цель: в дипломе добавить вход и роли, не переписывая экраны. Заглушек не делаем: в курсовом нет ни страницы
входа, ни выбора роли, ни поддельного пользователя с паролем.

1. **Все запросы проходят через один клиент API.** `fetch` вызывается только в `src/api/client.ts`. В дипломе
   здесь появятся учётные данные и обработка окончания сессии.
2. **Сессия доступна только через `useAuth()`.** В курсовом хук возвращает локальную сессию без пользователя
   и со всеми правами. В дипломе меняется только `AuthProvider`.
3. **Экраны проверяют права, а не роли.** Компоненты знают только `can("rules.edit")`, а список прав лежит в
   `src/auth/permissions.ts`. Роли появятся там же, и экраны при этом не изменятся.
4. **Маршруты описаны одним списком с требуемым правом.** По нему строятся и меню, и защита маршрутов, поэтому
   новый экран нельзя случайно оставить без права.
5. **Кнопки действий обёрнуты в `<Can permission="...">`.** Сюда относятся действия, которые в FR-6.3 разделены
   по ролям: изменение НПА и правил, удаление, запуск аудита.
6. **Ошибки `401` и `403` уже обрабатываются.** Бэкенд пока их не отдаёт, но клиент различает их: `401` будет
   вести на вход, `403` показывает «Недостаточно прав».
7. **Данные пользователя не кладём в `localStorage`.** Весь кэш лежит в TanStack Query, и при выходе его очищает
   один вызов. Так следующий пользователь не увидит чужие данные.
8. **В шапке оставлено место для меню пользователя.** Сейчас оно пустое.

Соответствие ролей и прав в курсовом не определяем: это решение принимается в начале работы над дипломом, см.
[`DIPLOMA.md`](../DIPLOMA.md). Названия прав в разделе 5 рабочие и могут измениться. Проверка в
интерфейсе только скрывает лишнее: настоящая защита должна быть на сервере.

## 4а. Подготовка к смене языка и темы

Цель: в дипломе добавить переключение языка интерфейса и цветовой темы, не переписывая экраны. Переключателей в
курсовом нет.

1. **Тексты только из словаря.** Все надписи, сообщения об ошибках и названия статусов берутся по ключу через
   `t("audit.run")` из `src/i18n/ru.ts`. В компонентах нет строк для пользователя. Словарь пока один, без
   библиотеки переводов; в дипломе к нему добавятся другие языки.
2. **Даты и числа через `Intl`.** Локаль задаётся в одном месте, поэтому `toLocaleString("ru-RU")` в компонентах
   не пишется.
3. **Цвета только через переменные CSS.** Компоненты используют смысловые цвета Tailwind (`bg-background`,
   `text-muted-foreground`, `severity-critical`), а сами значения лежат в одном файле стилей. Классы вроде
   `bg-red-500` в компонентах не используются. Тогда тёмная тема в дипломе задаётся только новыми значениями
   переменных.
4. **Цвета критичности тоже переменные.** У каждого уровня есть цвет фона подсветки, рамки и метки, поэтому их можно
   подобрать для каждой темы отдельно.
5. **Тексты модели не переводятся.** Пояснения и рекомендации приходят на языке документа и показываются как есть.

### Правила подсветки

Эти правила следуют из того, как устроен отчёт:

1. **Смещения.** `start_char` и `end_char` считаются в символах Python (кодовые точки), а строки JavaScript в
   единицах UTF-16. Эмодзи или редкий символ перед нарушением сдвинули бы всю подсветку, поэтому нужно
   преобразование смещений и тест на него.
2. **Пересечения.** Текст режется по всем границам нарушений, каждый кусок знает свои нарушения и окрашен по
   самой высокой критичности. Клик по куску с несколькими нарушениями показывает их все.
3. **Нарушения без позиции.** Если смещений нет, нарушение остаётся в списке с пометкой «Без привязки к тексту»,
   а прокрутки у него нет.
4. **Рекомендация.** Сначала берётся рекомендация модели из `neural_analyses` (связь по `finding_key`), затем
   `finding.recommendation`, заданная в ручном правиле. Без `finding_key` у старых отчётов пояснения нет.
5. **Безопасность.** Текст документа и ответы модели выводятся только как текст React, без
   `dangerouslySetInnerHTML`. Переносы строк сохраняются через `white-space: pre-wrap`.

**Готово, когда** на примерах из `backend/examples/` `remote_work_agreement.txt` показывает нарушения с верной
подсветкой, а `compliant_remote_work_agreement.txt` показывает отчёт без нарушений. Тесты покрывают нарезку текста
и смещения.

## 9. Долгие запросы и ошибки

Загрузка НПА, аудит и `reprocess` выполняются одним долгим запросом без данных о прогрессе, поэтому индикатор
не показывает проценты. На это время кнопка запуска блокируется, а страница предупреждает, что операция идёт.
Клиент не должен сам повторять запросы, вызывающие модель: лимит на бесплатном тарифе составляет 15 запросов в
минуту, а повторный запрос снова его расходует. Повтор доступен только по кнопке.

| Код                                                  | Что показать                                                   |
|------------------------------------------------------|----------------------------------------------------------------|
| `model_rate_limited`                                 | Превышен лимит запросов, повторить через минуту                |
| `model_timeout`                                      | Модель не ответила вовремя, кнопка повтора                     |
| `model_provider_error` и другие `503`                | Модель недоступна, отчёт не создан, кнопка повтора             |
| `audit_configuration_required`                       | Переход на настройку аудита                                    |
| `no_applicable_rules`                                | Для документа нет правил, ссылка на НПА и настройку            |
| `document_too_large_for_audit`, `document_too_large` | Документ слишком большой                                       |
| `empty_document`, `document_parse_error`             | Файл не удалось прочитать, например, скан без текста           |
| `rag_index_error`                                    | **Предупреждение:** изменение сохранено, но индекс не обновлён |

Текст берётся из словаря по коду ошибки, а `message` бэкенда показывается только как технические детали для
неизвестных кодов.

## 10. Проверка на настоящей модели

Проверяем только на маленьких файлах из `backend/examples/` и делаем паузы, чтобы не превысить лимит. Для
ручной проверки используем отдельную базу через `EDM_DATABASE_URL`. Автоматические тесты не обращаются к модели.
