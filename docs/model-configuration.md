# Настройка моделей

Файл `backend/config/models.toml` описывает профили моделей, пресеты и ограничения обработки. Секреты в
него не записываются: API-ключ передаётся через переменную окружения, указанную в `api_key_env`.

## Какие модели нужны

Система всегда работает с моделями: заглушек и резервных режимов нет. Без `EDM_MODEL_PRESET` API не
запускается. Пресет связывает три профиля:

| Профиль     | Для чего используется                                                       |
|-------------|-----------------------------------------------------------------------------|
| `embedding` | RAG-индекс и рекомендации при выборе правил                                 |
| `extractor` | извлечение правил из НПА, определение типа документа, извлечение сущностей  |
| `llm`       | подтверждение и объяснение нарушений, общая сводка                          |

```toml
[profiles.embedding.<name>]
[profiles.llm.<name>]
[profiles.extractor.<name>]

[presets.<name>]
embedding = "<embedding-profile>"
llm = "<llm-profile>"
extractor = "<extractor-profile>"
```

Готовые пресеты:

| Пресет             | Модели                                                       | Что нужно                                  |
|--------------------|--------------------------------------------------------------|--------------------------------------------|
| `google-ai-studio` | `gemini-3.1-flash-lite`, эмбеддинги `gemini-embedding-2`     | `GEMINI_API_KEY`                           |
| `lm-studio`        | `google/gemma-4-e4b` и локальная модель эмбеддингов          | запущенный сервер LM Studio                |
| `openrouter`       | модель OpenRouter и локальная модель эмбеддингов             | `OPENROUTER_API_KEY` и локальный сервер    |

На настоящих данных проверен только `google-ai-studio`.

## Поля профиля

| Поле                        | Обязательно             | Описание                                            |
|-----------------------------|-------------------------|-----------------------------------------------------|
| `provider`                  | да                      | `openai-compatible` или `google-ai-studio`          |
| `model`                     | да                      | Точное имя модели на сервере                        |
| `base_url`                  | для `openai-compatible` | Адрес API без `/embeddings` и `/chat/completions`   |
| `api_key_env`               | для облачного API       | Имя переменной окружения с ключом                   |
| `dimension`                 | для embedding           | Размерность вектора, которую возвращает модель      |
| `structured_output`         | для llm                 | `false`, `"json_object"` или `"json_schema"`        |
| `temperature`               | нет                     | Температура, по умолчанию `0.1`                     |
| `max_tokens`                | нет                     | Размер ответа, по умолчанию `2000`                  |
| `request_timeout_seconds`   | нет                     | Таймаут запроса, по умолчанию `30`                  |
| `retry_attempts`            | нет                     | Повторы при ответах 429, 500 и 503, по умолчанию `3` |
| `retry_backoff_factor`      | нет                     | Множитель паузы между повторами, по умолчанию `1.0` |
| `inter_chunk_delay_seconds` | нет                     | Пауза между фрагментами, по умолчанию `0`           |

Важные значения:

- **`structured_output`.** Значение `"json_schema"` заставляет модель соблюдать схему ответа. Значение
  `"json_object"` подходит для сервера с режимом JSON без схемы, `false` отключает параметр. Приложение
  в любом случае само проверяет ответ. Без схемы модель может вернуть недопустимое правило: такой
  фрагмент считается неудачным, и правила акта не публикуются.
- **`max_tokens`.** У профилей Google стоит `8192`: при меньшем значении длинный список сущностей или
  пояснений обрезался.
- **`temperature`.** У профиля извлечения Google стоит `0`, чтобы повторная обработка акта давала те же
  правила и ту же важность.
- **`dimension`.** Должна точно совпадать с ответом модели. После смены модели или размерности индекс
  нужно пересобрать: несовместимый индекс отклоняется.

## Ограничения запросов

На бесплатном тарифе Gemini у модели лимит 15 запросов в минуту. При его превышении API отвечает
`429 model_rate_limited`, а извлечение правил останавливается на первой такой ошибке. Запас даёт
`inter_chunk_delay_seconds` профиля `extractor`: например, значение `5` позволит обрабатывать
фрагменты с паузой. Эта пауза действует при извлечении правил и сущностей.

Таймаут даёт `504 model_timeout`, остальные сбои дают `503`. Отчёт при этом не создаётся, а документ
получает статус `error`.

## Что и в каком объёме получают модели

Лимиты документов задаёт секция `[document_processing]`.

| Запрос                  | Что получает модель                                              | Параметры                                                     |
|-------------------------|------------------------------------------------------------------|---------------------------------------------------------------|
| Тип документа           | активный каталог типов, начало и конец текста                    | `classification_head_chars`, `classification_tail_chars`      |
| Извлечение сущностей    | весь документ частями                                            | `entity_chunk_max_chars`, `entity_chunk_overlap_chars`        |
| Интерпретация нарушений | нарушения пакетами по 10, цитаты норм, текст вокруг нарушения    | размер пакета задан в коде                                    |
| Извлечение правил       | фрагмент НПА, название акта, каталог типов                       | `[legal_act_processing.chunking]`: `max_chars`, `overlap_chars` |

- **Порог уверенности.** Тип документа или правила подтверждается при уверенности не ниже
  `classification_min_confidence` (`0.7`). Иначе документ получает статус `needs_review`, а правило
  область `unknown` и автоматически не применяется.
- **Типы правил.** Модель определяет их отдельно для каждого правила. Типы, заданные у НПА вручную, важнее:
  ответ модели хранится в `applicability_auto` и возвращается, если ручные типы снять. Новые типы модель
  только предлагает, решение принимает человек.
- **Размер документа.** Если частей больше `entity_max_chunks`, аудит отвечает
  `413 document_too_large_for_audit` до первого запроса к модели.
- **Подтверждение нарушений.** Нарушения правил срока и числа модель подтверждает или отклоняет в том же
  запросе, что и пояснение. Отклонённые попадают в `summary.rejected_candidates`. Если нарушений нет,
  модель всё равно вызывается и возвращает только сводку. Несколько пакетов требуют отдельного запроса
  на сводку.
- **Что модель не решает.** Она не может изменить важность, позицию нарушения и код правила, а ссылки на
  НПА формирует сервер. Ответ с неизвестным `finding_key` или без вердикта отклоняется: аудит завершается
  ошибкой.
- **Важность.** Модель выбирает её при извлечении правила по критериям из запроса, и человек может
  изменить её через `PATCH /api/rules/{id}`.

Секция `[legal_act_processing]` содержит также `source_language` (`auto`, `ru` или `en`, переопределяется
через `EDM_SOURCE_LANGUAGE`). Там же записан `processing_version`, который сохраняется у НПА.
Параметры `max_prompt_chars`, `max_response_tokens` и `max_rules_per_chunk` проверяются при загрузке
настроек, но обработка их пока не использует. `extraction_schema_version` и `prompt_version` только
фиксируют версии.

## Настройка окружения

```bash
cd backend
cp .env.example .env    # затем укажите пресет и ключ
```

Файл `backend/.env` загружается автоматически, но уже заданные переменные окружения важнее его значений.
Если в профиле оболочки есть другой `GEMINI_API_KEY`, выполните `set -a; source .env; set +a`. Другой файл
настроек задаётся через `EDM_MODEL_CONFIG`.

Нельзя хранить реальные ключи в `models.toml`, `.env.example` и Git. Тесты не требуют сети и ключей:
дублёры моделей находятся в `backend/tests/fakes.py` и в рабочий код не входят.

### LM Studio

1. Запустите сервер OpenAI-совместимого API в LM Studio, обычно это `http://localhost:1234/v1`.
2. Укажите в профилях фактические имена загруженных моделей эмбеддингов и чата.
3. Запустите с пресетом:

```bash
EDM_MODEL_PRESET=lm-studio uvicorn edm_auditor.api.app:create_app --factory --reload
```

Модель эмбеддингов должна быть загружена отдельно от модели чата.

### OpenRouter

```bash
export EDM_MODEL_PRESET=openrouter
export OPENROUTER_API_KEY="your-key"
```

Профиль эмбеддингов этого пресета по-прежнему указывает на локальный сервер. Чтобы получать эмбеддинги
через облако, создайте отдельный профиль и укажите его в пресете. У текущего профиля OpenRouter
`structured_output = false`, поэтому соблюдение схемы ответа не гарантировано.

## Новый пресет

Создайте профили и свяжите их. Имена должны совпадать с именами профилей соответствующего раздела:

```toml
[presets.local-dev]
embedding = "local-multilingual"
llm = "lm-studio"
extractor = "gemma"
```
