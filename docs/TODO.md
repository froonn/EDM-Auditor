## 1. Доработка бэкенда

Задачи получены при проверке API на настоящем Gemini.

### Корректность аудита

- [ ] **Пропущенные нарушения.** Требование «не реже двух раз в месяц» не проверяется: в `payroll_order`
  «один раз в месяц» не определяется, потому что в тексте нет срока, который можно сравнить с
  нормой. Такие требования может закрыть только семантический аудит, поэтому пока это ограничение.
- [ ] **Правила `semantic`.** Они не выполняются, но модель всё ещё может их создавать. Нужно запретить
  такой тип при извлечении, пока семантический аудит отложен до диплома.
- [ ] **Важность нарушений.** Модель назначает её при извлечении правил, поэтому между запусками
  одно правило бывает `high` и `critical`.

### Ошибки API

- [ ] **Запись в базу во время аудита.** Транзакция открыта на всё время вызовов моделей, поэтому
  параллельная загрузка документа через 5 секунд падает с `500`.
- [ ] **`PATCH /api/legal-acts/{id}` с `title: null`** отвечает `500`, нужен `422`.
- [ ] **Смена текста НПА.** Правила остаются прежними, а статус `completed`, хотя цитаты ссылаются на
  старый текст. Нужно показывать, что акт требует повторной обработки.
- [ ] **Проверка правила при создании.** `POST /api/rules` принимает неверный regex и пустые параметры,
  а при аудите такое правило пропускается. Нужен `422`.
- [ ] **Повторяющиеся НПА.** Можно создать два акта с одним кодом, и одинаковые акты дают одинаковые
  нарушения по нескольку раз. Нужен `409` при совпадении кода.
- [ ] **`title` при загрузке документа** читается только из query, а значение из формы игнорируется.
- [ ] **Единый формат ошибок.** Ответы `404` и `405` отдают `{"detail": ...}`, `500` отдаёт простой
  текст, а `422` показывает пути к файлам сервера.
- [ ] **Лишние файлы в `data/uploads`.** Файлы загруженных и отклонённых НПА остаются на диске, хотя
  текст акта хранится в базе.
- [ ] **Пустые файлы.** Документ и НПА без текста принимаются, а для НПА статус `completed`.

- [ ] **Редактирование правил (FR-5.2):** сейчас меняется только применимость, а `is_active` через API
  не задать.
- [ ] **Удаление документа** вместе с его файлом и отчётами.

### Сделано

- [x] **Ложные нарушения в правилах срока и числа.** Модель подтверждает каждое такое нарушение по
  норме и окружающему тексту, в том же запросе, что и пояснение. Отклонённые кандидаты сохраняются в
  `summary.rejected_candidates`.
- [x] **Дата принималась за срок.** «5 числа следующего месяца» больше не считается сроком.
- [x] **Ошибочный пример** `compliant_remote_work_agreement.txt` исправлен.
- [x] **Тесты на настоящих ответах модели:** `tests/fixtures/recorded_gemini_audit.json`.
- [x] **Ссылки на НПА в пояснениях.** Их формирует сервер из правила, модель на них не влияет.
- [x] **Язык пояснений** теперь совпадает с языком документа.
- [x] **Таймаут Google-клиента.** Таймаут берётся из профиля модели, при его истечении API отвечает
  `504 model_timeout`.
- [x] **Загрузка НПА не блокирует сервер.** Обработка вынесена в пул потоков. Загрузка НПА и аудит
  остаются одним долгим запросом без прогресса: на маленьких файлах этого достаточно.
- [x] **Отдельная ошибка при превышении лимита модели.** API отвечает `429 model_rate_limited`, и
  фронт может предложить повторить действие позже.

## Отложено

- **Большие НПА** вроде Трудового кодекса: один неудачный фрагмент останавливает публикацию всех
  правил акта, а число запросов быстро превышает лимит модели.
- **`alembic.ini`:** путь к базе задан жёстко, поэтому миграции всегда идут в
  `data/edm_auditor.sqlite3`.
- **Порог уверенности 0.7:** проверен только на нескольких примерах.
