# Журнал разработки EDM-Auditor

Правила ведения описаны в локальном файле `AGENTS.md`, раздел Development Log.

## Текущее состояние

Курсовой проект БГУИР: аудит электронных документов на соответствие законодательству
Республики Беларусь. Обзор и запуск описаны в корневом [`README.md`](../README.md), требования в
[`TASK.md`](TASK.md), API в [`backend/README.md`](../backend/README.md), отладка в [`DEBUG.md`](DEBUG.md).
Планы завершённых этапов лежат в [`archive/`](archive/) и не обновляются. Требования к диплому собраны в
[`DIPLOMA.md`](DIPLOMA.md).

**Работает** (бэкенд на FastAPI, SQLAlchemy и SQLite):

- разбор документов TXT, PDF и DOCX;
- извлечение правил из НПА через LLM, их проверка и атомарная публикация;
- каталог типов документов, определение типа документа и типов каждого правила через LLM,
  предложения новых типов с решением человека;
- выбор применимых правил: режимы `automatic`, `manual`, `combined` и подтверждённый `all`,
  предпросмотр и сохранение конфигурации в отчёте;
- аудит: проверки правил кодом и обязательные вызовы LLM, при сбое модели ответ `503` без отчёта;
  длинные документы читаются частями, все нарушения объясняются пакетами.

**Интерфейс** (`frontend/`, React, TypeScript, Vite, Tailwind CSS, см.
[`frontend/README.md`](../frontend/README.md)): список и загрузка документов, подтверждение типа, настройка
и предпросмотр аудита, экран аудита с подсветкой нарушений и карточками, управление НПА, правилами и типами
документов, выгрузка отчёта в HTML. Swagger UI на `/docs` для работы больше не нужен.

**Запуск на защите:** `docker compose up --build -d`, интерфейс на <http://localhost:8080>, см.
[`docker.md`](docker.md).

**Не сделано:**

- экспорт отчёта в PDF и DOCX с комментариями перенесён в диплом, курсовой выгружает HTML;
- авторизация, роли, семантический аудит, извлечение фактов, готовый фрагмент для вставки, конструктор
  документов и ЭЦП перенесены в
  дипломный проект: правила `semantic` нельзя создать ни через модель, ни через API, а RAG показывает
  лишь рекомендации.

**Известные проблемы** (полный список задач в [`TODO.md`](TODO.md)):

- частота выплат не проверяется: норма «не реже двух раз в месяц» становится правилом `duration`, а в
  документе «один раз в месяц» нет срока в днях, поэтому нарушение не находится;
- требование «не позднее 5 числа следующего месяца» модель пропускает при извлечении правил без следа в
  диагностике: проверки дня месяца нет;
- вердикт модели проверен только на 6 примерах из `examples/`, на других документах он может
  ошибаться;
- повторная обработка НПА пересоздаёт его правила, поэтому их ручные правки теряются;
- стабильность критичности проверена только на трёх примерах НПА;
- при перегрузке Gemini отвечает `503`, и аудит падает;
- `load_dotenv` не перезаписывает заданные переменные: если в окружении есть другой
  `GEMINI_API_KEY`, для ключа из `backend/.env` нужен `set -a; source .env; set +a`;
- `alembic.ini` задаёт путь к базе жёстко и не читает `EDM_DATABASE_URL`: миграции всегда идут в
  `data/edm_auditor.sqlite3`;
- один неудачный фрагмент НПА останавливает публикацию всех правил акта: на Трудовом кодексе модель
  дала неточные цитаты и неполные ответы, поэтому большие акты пока не загружаются;
- проверка на 47 фрагментах упёрлась в квоту Gemini (`429`): для больших актов и документов нужна
  пауза `inter_chunk_delay_seconds`;
- порог уверенности 0.7 проверен только на нескольких примерах, а модель почти всегда ставит 0.8–1.0;
- порог RAG-рекомендаций 0.5 выбран без замеров;
- в Docker работает только пресет `google-ai-studio`: `lm-studio` и `openrouter` обращаются к `localhost`
  контейнера.

**Локальные данные** (в Git не входят): схема `backend/data/edm_auditor.sqlite3` соответствует ревизии
`0009_finding_snapshot`, но база создана сервером без Alembic и не содержит `alembic_version`. Перед
`alembic upgrade head` её нужно пометить: `alembic stamp head`. Перенос в Docker описан в
[`docker.md`](docker.md).

### 2026-11-06: управление НПА, правилами и типами документов

- Экран НПА: загрузка TXT с полями и типами через ту же область перетаскивания, что и у документов, поиск,
  страница НПА с изменением, диагностикой фрагментов и правилами акта. Повторная обработка и удаление только
  после предупреждения. При изменении НПА отправляются только изменённые поля.
- Экран правил: фильтры, включение и выключение, создание и изменение с параметрами по типу проверки,
  отдельная форма применимости с выбором модели. Ошибку параметров сервер объясняет рядом с формой.
- Экран типов документов: каталог с отключёнными типами, изменение, отключение и включение, решения по
  предложениям модели.
- Страницы НПА, правила, типов документов и настройки аудита разложены на две колонки и занимают всю ширину.
- Бэкенд: правило, все типы которого отключены, нельзя включить (`409 rule_document_types_inactive`). Иначе
  проверку при отключении типа можно было обойти: выключить правила, отключить тип и включить их снова.
- Отключённые типы подписаны в списках, а в форме применимости видны, чтобы с них можно было снять отметку.
  Переключатель правила блокируется, пока сервер не ответит и список не обновится: сервер пересобирает
  индекс перед ответом. Можно переключать несколько правил сразу, ошибки показываются по каждому правилу.
- Текст НПА в редакторе показывается по абзацу на строку, а при сохранении строки снова становятся абзацами.
  Неизменённый текст не отправляется, поэтому правила не помечаются устаревшими.
- Страница правила загружает весь список правил: у API нет запроса одного правила, задача в `TODO.md`.
- Через прокси на Gemini загружен `legal_act_payments.txt` на копии базы: 2 правила. Весь сценарий из
  `backend/examples/README.md` в браузере ещё не проходили.

### 2026-11-05: экран аудита в интерфейсе

- Документ в статусе `processing` проверяется каждые 5 секунд, а повторный запуск требует подтверждения.
- Бэкенд: фильтр `document_id` в `GET /api/reports` и сводка `latest_report` у документа.
- На Gemini проверено на копии базы: `remote_work_agreement.txt` дал 2 нарушения с верными позициями,

### 2026-11-05: API для фронта, запрет `semantic`, стабильная важность

- `GET /api/documents/{id}` отдаёт текст документа, а нарушения содержат `finding_key` и копию данных
  правила, акта и нормы. Миграция `0009_finding_snapshot` заполняет эти поля и для старых отчётов,
  насколько правила ещё существуют. **Нужно вручную выполнить `alembic upgrade head`.**
- Новые эндпоинты: `PATCH /api/rules/{id}`, `DELETE /api/documents/{id}`, `GET /api/reports/{id}`,
  `PATCH /api/document-types/{code}`. Списки отдают `X-Total-Count`, правила фильтруются по области.
- Модель и API больше не создают правила `semantic`: они всё равно не выполняются.
- Важность выбирается по заданным критериям, температура извлечения на Gemini равна 0. На трёх
  примерах НПА три запуска дали одинаковую важность. Прогон на настоящем Gemini прошёл на отдельной базе.
- Экспорт отчёта отложен до фронта. Ручные правки правил теряются при повторной обработке НПА.

### 2026-11-05: исправлены ошибки API

- Запрещено очищать `code`, `title` и `article_text` у НПА, код НПА теперь уникален на уровне API.
  Ограничения в базе нет: миграция упала бы на уже существующих повторах.
- После смены текста НПА статус `needs_reprocessing`, пока не выполнен `reprocess`.
- `POST /api/rules` проверяет параметры (`422 invalid_rule_parameters`), пустые файлы дают
  `400 empty_document`, `title` документа читается из формы.
- Файлы НПА не хранятся: текст лежит в базе. Старые файлы в `data/uploads` остались, их никто не читает.
- Все ошибки отдаются как `{"error": {"code", "message"}}`, без путей сервера.

### 2026-11-05: аудит не блокирует запись в базу

- Транзакция была открыта на все вызовы моделей, поэтому параллельная запись падала с `500`. Теперь
  статус сохраняется до вызовов, а отчёт после них. Статус `processing` виден во время аудита.

### 2026-11-05: подтверждение нарушений через LLM

- Правила срока и числа сравнивают все значения документа, поэтому модель теперь подтверждает каждое
  нарушение по норме и окружающему тексту. Новых запросов нет: вердикт приходит вместе с пояснением.
  Отклонённые кандидаты лежат в `summary.rejected_candidates`, а нет вердикта у кандидата: `503`.
- Ссылки на НПА формирует сервер, пояснения пишутся на языке документа, дата больше не принимается
  за срок. Исправлен пример `compliant_remote_work_agreement.txt`.
- Регрессионные тесты работают на сохранённых ответах Gemini. Новые отчёты получают поле
  `rejected_candidates`, старые остаются читаемыми.
- Семантический аудит и извлечение фактов перенесены в дипломный проект.
