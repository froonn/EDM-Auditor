# Оценка качества

Размеченный набор НПА и документов, на котором замеряется извлечение правил и аудит. Нужен для переработки
из [`docs/feature-rules-audit-rework.md`](../../docs/feature-rules-audit-rework.md): каждый этап сравнивается
с базовым замером.

## Набор

`corpus/acts/` — 4 небольших синтетических НПА с главами, пунктами, переносами строк и списками с вводной
фразой. `corpus/documents/` — 11 документов: с нарушениями, без нарушений, с условиями, записанными другими
словами, с «чужими» значениями того же вида (доставка 20 рублей рядом с компенсацией за интернет) и с
условием применения нормы (ребенок до трех лет, работник моложе 18 лет).

Разметка в `corpus/labels.toml`:

- **норма** — цитата из НПА, ожидаемый вид (`value`, `frequency`, `day_of_month`, `text`) и признак
  `checkable`: для норм не о документах («контроль осуществляет главный бухгалтер») правило создаваться
  не должно;
- **нарушение** — норма и цитата из документа; без цитаты — отсутствующее условие. Все остальные проверяемые
  нормы актов документа считаются выполненными.

Переносы строк и пробелы в цитатах совпадают с любыми пробельными символами. Цитата должна встречаться в
файле ровно один раз.

## Запуск

Из `backend/` с активированным окружением:

```bash
python -m edm_auditor.evaluation check                    # проверить разметку, без модели
set -a; source .env; set +a                               # ключ из .env важнее ключа оболочки
python -m edm_auditor.evaluation run --label baseline     # прогон с настоящей моделью
python -m edm_auditor.evaluation score results/<файл>.json  # пересчитать сохранённый прогон
```

`run` поднимает API во временной папке, загружает все НПА, затем каждый документ, подтверждает его тип из
разметки и проверяет правилами его актов в режиме `manual`. Применимость правил к типам документов здесь не
оценивается. Между запросами к модели выдерживается пауза `--min-interval` (4,5 с, под лимит 15 запросов в
минуту бесплатного Gemini). Прогон всего набора — около 40 запросов и 4–5 минут.

Результат записывается в `results/<дата>-<метка>.json` (ответы API и метрики) и `.md` (сводка). Журнал
прогона `.log` в Git не попадает.

## Метрики

| Метрика                   | Что считает                                                                                          |
|---------------------------|------------------------------------------------------------------------------------------------------|
| Полнота извлечения        | доля проверяемых норм, у которых есть правило: цитата правила пересекает норму                       |
| Лишние правила            | правила, цитата которых не пересекает ни одну размеченную норму                                      |
| Точность и полнота аудита | по нарушениям: находка верна, если её правило относится к норме нарушения и место совпадает          |
| Причины ложных находок    | `norm_is_met` — норма выполнена, `wrong_place` — не то место, `rule_without_norm` — лишнее правило   |
| Причины пропусков         | `no_rule` — правила нет, `not_detected` — правило есть, но не сработало, `audit_failed` — аудит упал |
| Полнота по видам норм     | полнота аудита отдельно для `value`, `frequency`, `day_of_month`, `text`                             |
| Запросы к модели          | по видам: правила, тип документа, сущности, пояснения, эмбеддинги                                    |

Повторная находка того же нарушения считается повтором и в точность не входит.
